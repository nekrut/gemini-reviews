### 1. SUMMARY AND OVERALL IMPACT STATEMENT

#### Executive Summary
This software paper introduces `Scanpy`, a modular Python-based toolkit for large-scale single-cell transcriptomic analysis, junto with `AnnData`, a language-independent HDF5-backed and sparse-matrix-compatible container for annotated observation $\times$ feature matrices. `Scanpy` unifies canonical single-cell workflows—preprocessing, confounding regression, highly variable gene selection, PCA, neighborhood graph construction via submatrix block matrix multiplication, $t$-SNE, Fruchterman–Reingold graph drawing, diffusion maps, Louvain clustering, cluster marker differential expression, diffusion pseudotime (`DPT`), and regulatory network simulation—around a single shared neighborhood graph stored in `AnnData`. The authors benchmark `Scanpy` across three 10x Genomics datasets: (1) reproducing the 2,700-PBMC `Seurat` tutorial with 5x–90x step-wise speedups, (2) reproducing the 68,579-PBMC `Cell Ranger R kit` workflow (Zheng et al., 2017) with 5x–16x speedups (Figure 1a,b), and (3) clustering and visualizing 1.3 million E18 mouse brain cells without subsampling in a few hours on an 8-core server (Figure 1c). All source code (`scanpy`, `anndata`) and six complete benchmark notebooks (`scanpy_usage`) are openly archived on GitHub and PyPI under the BSD-3 license.

`Scanpy` and `AnnData` fill a critical infrastructure gap in single-cell genomics by bringing sparse, out-of-core HDF5-backed data structures and parallelized neighborhood graph reuse to the Python scientific and machine-learning ecosystem. The primary limitation of the manuscript text itself is its extreme brevity: exact wall-clock runtimes, peak RAM footprints, hardware specifications, and quantitative clustering/DE concordance metrics (e.g., Adjusted Rand Index or marker gene rank correlations against `Seurat` and `Cell Ranger`) are not tabulated in the article, requiring readers to inspect external GitHub notebooks (`theislab/scanpy_usage`).

### 2. SPECIFIC CONCLUSIONS AND ASSESSMENT OF SUPPORT

#### Detailed Rubric Evaluation

* **Claim 1 — `Scanpy` achieves 5x–90x step-wise speedups over `Seurat` (on 2,700 PBMCs) and 5x–16x speedups over the `Cell Ranger R kit` (on 68,579 PBMCs) while reproducing canonical cell-type clusters, marker genes (*MS4A1* in B cells), and `CD34+` branching trajectories: [Well Supported].**  
  Figure 1a,b and the linked public benchmark repositories (`170505_seurat` and `170503_zheng17`) substantiate the step-wise speedups and biological reproduction of the Zheng et al. (2017) PBMC cell types. However, the manuscript text does not report quantitative agreement metrics (e.g., Adjusted Rand Index or Normalized Mutual Information between `Scanpy` and `Seurat`/`Cell Ranger` cluster assignments, or Spearman correlation of highly variable gene dispersions and DE $p$-values) to quantify how closely the faster Python implementations match the reference R outputs.

* **Claim 2 — `Scanpy` and `AnnData` scale to 1.3 million mouse brain cells without subsampling in a few hours on an 8-core server: [Moderately Supported].**  
  Figure 1c and the `170522_visualizing_one_million_cells` repository demonstrate end-to-end PCA, neighborhood graph construction, Louvain clustering, and visualization on the 1.3M-cell 10x Genomics E18 mouse brain dataset. In the main text (line 34), however, the resource consumption is stated only qualitatively as *"in a few hours of computing time on eight cores of a small computing server"* without specifying the exact wall-clock time (in minutes/hours), peak RAM usage (in GB), or whether in-memory sparse matrices (`CSR`/`CSC`) or disk-backed HDF5 (`backed` mode) were used for the 1.3M-cell run.

* **Claim 3 — Aggregating observation rows into submatrices and using parallelized matrix multiplication accelerates $k$-nearest-neighbor graph construction over `scikit-learn`, and reusing a single graph across clustering, visualization, and pseudotime avoids inconsistent representations: [Moderately Supported].**  
  Line 40 describes the architectural design of the neighborhood graph class and states that *"The computation of neighborhood relations is much faster than in the popular reference package [27] [`scikit-learn`]."* While reusing a single shared $k$-NN graph across Louvain clustering, diffusion maps, and force-directed layout is a clear methodological and computational improvement, no standalone runtime comparison or exact vs. approximate nearest-neighbor recall benchmark against `scikit-learn` (`KDTree` / `BallTree` / brute-force pairwise distances) is presented in the paper.

* **Claim 4 — Existing R-based single-cell frameworks (`Seurat`, `Monocle`, `scater`, `scran`, `Cell Ranger`) cannot scale to datasets of more than one million cells: [Moderately Supported].**  
  Lines 17 and 48 motivate `Scanpy` by noting that established R frameworks do not scale to $>10^6$ cells (while acknowledging in line 48 that an HDF5-backed C++ matrix library for R, `DelayedArray`/`beachmat` [32], was posted just prior to submission). Because the 1.3M-cell benchmark was not attempted in `Seurat` or `Cell Ranger R kit` up to a specified memory ceiling (e.g., 64 GB or 128 GB RAM), the exact sample-size/memory failure threshold of the R baselines is not empirically documented in Figure 1b.

### 3. CONSTRUCTIVE AND DOABLE SUGGESTIONS FOR IMPROVEMENT

#### Major Issues, Minor Issues & Concrete Recommendations

#### 1. Add a Self-Contained Benchmark Table Reporting Exact Runtimes, Peak RAM, and Hardware Specs Across All Three Datasets (Major Issue)
* **WHY:** Relying on external GitHub links (`scanpy_usage`) for the exact timing and memory numbers of the 2,700-PBMC, 68,579-PBMC, and 1.3M-brain-cell benchmarks makes the archival publication incomplete on its own.
* **WHAT:** Include a compact 1-page table in Results or Methods listing, for each benchmark step (preprocessing/filtering, regressing out confounders, PCA, neighborhood graph, $t$-SNE, Louvain clustering, marker DE, and DPT), the exact wall-clock time (seconds) and peak memory (GB) for `Scanpy` (in-memory and HDF5-backed modes), `Seurat`, and `Cell Ranger R kit`, along with the CPU model and total system RAM.
* **HOW:** Extract the summary timings and memory profiles directly from the three existing GitHub notebooks (`170505_seurat`, `170503_zheng17`, `170522_visualizing_one_million_cells`) and format them as Table 1.

#### 2. Quantify Numerical Concordance Between `Scanpy` and `Seurat` / `Cell Ranger` Outputs (Major Issue)
* **WHY:** When re-implementing preprocessing, covariate regression, dispersion-based variable gene selection, and Louvain clustering in Python for 5x–90x speedups, users need to know whether results are numerically identical or algorithmically equivalent up to stochastic $t$-SNE / Louvain initialization seeds.
* **WHAT:** Report the overlap (Jaccard index) of selected highly variable genes, Pearson correlation of principal component loadings, Adjusted Rand Index (ARI) of Louvain clusters, and rank correlation of cluster marker genes between `Scanpy` and `Seurat` (2.7k PBMCs) and `Cell Ranger` (68.5k PBMCs).
* **HOW:** Compute these four concordance statistics on the outputs already generated in `170505_seurat` and `170503_zheng17` and report them in Section 2 ("SCANPY is benchmarked in comparisons with established packages").
