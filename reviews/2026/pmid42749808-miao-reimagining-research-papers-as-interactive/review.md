### 1. SUMMARY AND OVERALL IMPACT STATEMENT

This manuscript introduces `Paper2Agent`, an automated multi-agent framework built on `Claude Code` that converts scientific papers and their associated code or data repositories into interactive Model Context Protocol (MCP) servers (`Paper Agents`). The pipeline decomposes conversion into four subagents: an environment manager that scans repositories and discovers tutorials (`Step 1`), a tutorial executor that configures dependencies and runs tutorial notebooks (`Step 2`), a tool extractor that wraps core code blocks into MCP functions with standardized inputs/outputs (`Step 3`), and a test verifier (`Step 4`) that runs unit tests against reference tutorial outputs before deploying the MCP server to Hugging Face Spaces. The authors evaluate `Paper2Agent` across three methodological case studies (`AlphaGenome`, `Scanpy`, and `TISSUE`), report feasibility tests on 100 recent computational biology repositories (`74/100` converted; median synthesis time `41 min`, median API cost `$1.86`), 10 non-biology repositories (`10/10`), and 26 primary biological data repositories (`26/26`), and present two multi-agent "AI co-scientist" discovery vignettes: fine-mapping 39 attention-deficit/hyperactivity disorder (ADHD) GWAS loci with `AlphaGenome` (`Fig. 3`, `Supplementary Table 1`) and integrating a single-cell CRISPRi screen of autoimmune non-coding variants (`Paper 2`) with a CD4+ T cell Perturb-seq gene knockdown atlas (`Paper 1`) to prioritize `GPR137` over `BAD` at the psoriasis-associated `rs887314` locus (`Fig. 4`). Source code (`github.com/jmiao24/Paper2Agent`) and generated MCP servers are publicly available.

While packaging verified tutorial workflows into reusable MCP tools is a practical software engineering contribution, four methodological, statistical, and numerical defects undermine the manuscript's benchmark claims and biological conclusions. First, `Supplementary Table 1` (pp. 58–60 of the Supplementary Information) exhibits severe internal numerical contradictions: for more than 20 of the 39 ADHD loci, the `AlphaGenome` quantile scores cited inside the AI co-scientist's `interpretation` text do not match the numeric `splice`, `rna_seq`, `dnase`, and `chip_tf` columns of the very same row (and in 5 rows, column values are shifted into the wrong fields), directly contradicting the paper's central premise that wrapping tools into `Paper2Agent` eliminates LLM hallucination and reporting inconsistency. Second, the causal-gene prioritization at `rs887314` (`GPR137` over `BAD`, `Fig. 4`) rests on an asymmetric gene-exclusion rule introduced via human intervention (`Supplementary Note 9.2`, p. 50) and ignores local enhancer/promoter sharing (`rs887314` lies 981 bp from the `BAD` transcription start site [TSS], and CRISPRi targeting either `BAD` TSS or `GPR137` TSS strongly downregulates both genes). Third, the benchmark hypothesis tests (`Fig. 2b–c`, `Supplementary Note 4`) treat $n = 5$ stochastic LLM sampling runs on a fixed set of 15 queries as independent replicates, inflating statistical significance ($p = 4.2 \times 10^{-3}$ and $p = 8.1 \times 10^{-3}$) where item-level binomial testing across the 15 questions is non-significant, while simultaneously handicapping the `Claude + Repo` baseline via an asymmetric system prompt (`p. 23`). Fourth, the cost and speedup ratios reported in `Supplementary Note 7` (`p. 31`) contradict the raw dollar and runtime figures stated in the same sentence. These issues can be resolved through computational re-analysis, item-level statistical testing, table regeneration, and tempered causal claims without generating new wet-lab data.

### 2. SPECIFIC CONCLUSIONS AND ASSESSMENT OF SUPPORT

* **Claim 1 (`Paper2Agent` co-scientists reliably interpret `AlphaGenome` variant effects across 39 ADHD GWAS loci without hallucination, `Fig. 3e` & `Supplementary Table 1`): Methodologically Flawed / Contradicted by Supplementary Table 1.**  
  A core motivation of the manuscript is that standard LLM workflows hallucinate parameters or misreport outputs, whereas `Paper2Agent` ensures reliable, grounded execution (`Abstract`; `Main Text` p. 2). However, auditing `Supplementary Table 1` (`MOESM1_ESM.pdf`, pp. 58–60) reveals pervasive numerical contradictions between the table's quantitative `AlphaGenome` output columns (`splice`, `rna_seq`, `dnase`, `chip_tf`) and the quantile scores cited inside the AI co-scientist's `interpretation` column for the exact same locus and gene across more than half of the 39 loci:
  * **Locus 1 (`rs653953`, `PTPRF`):** The table columns report `splice = 0.9470497`, `rna_seq = 0.9847427`, `dnase = 0.64188623`, and `chip_tf = 0.67455524`, whereas the adjacent `interpretation` text states: *"(AlphaGenome quantile scores: RNA-seq = 0.459, DNase = 0.333, ChIP-TF = 0.363)."*
  * **Locus 10 (`rs17516470`, `CADM2`):** The table columns report `splice = 0.9708846`, `rna_seq = 0.9996424`, `dnase = 0.17133315`, and `chip_tf = 0.9071543`, whereas the `interpretation` text states: *"(AlphaGenome quantile scores: splice = 0.985, RNA-seq = 0.642, DNase = 0.363, ChIP-TF = 0.874)."*
  * **Locus 14 (`rs10074873`, `ZNF131`):** The table columns report `splice = 0.8908594`, `rna_seq = 0.9997094`, `dnase = 0.9978883`, and `chip_tf = 0.83002186`, whereas the `interpretation` text states: *"(AlphaGenome quantile scores: splice = 0.991, RNA-seq = 0.733, DNase = 0.431, ChIP-TF = 0.495)."*
  * **Locus 15 (`rs324886`, `MEF2C`):** The table columns report `rna_seq = 0.3225975`, `dnase = 0.78616506`, and `chip_tf = 0.9824973`, whereas the `interpretation` text states: *"(AlphaGenome quantile scores: RNA-seq = 0.823, DNase = 0.183, ChIP-TF = 0.782)."*
  * **Locus 17 (`rs358649`, `KCTD16`):** The table columns report `splice = 0` and `rna_seq = 0`, whereas the `interpretation` text cites *"`splice = 0.477, RNA-seq = 0.353`"* and argues that the variant acts through splicing and expression alongside chromatin accessibility.
  * **Locus 25 (`rs12277865`, `METTL15`):** The table columns report `splice = 0`, `rna_seq = 0`, `dnase = 0.8087958`, and `chip_tf = 0.9554709`, whereas the `interpretation` text states: *"(AlphaGenome quantile scores: splice = 0.935, RNA-seq = 0.961, DNase = 0.982, ChIP-TF = 0.722)."*
  * **Additional mismatched loci:** Similar numerical contradictions between the numeric columns and the AI-written interpretation text occur at Locus 8 (`UBA7`), Locus 12 (`EMCN`), Locus 19 (`FOXP2`), Locus 21 (`CER1`), Locus 23 (`SORCS3`), Locus 24 (`STK32C`), Locus 26 (`DUSP6`), Locus 28 (`PCDH17`), Locus 29 (`POU4F1`), Locus 31 (`SEMA6D`), Locus 32 (`TCF12`), Locus 33 (`HMG20A`), Locus 35 (`CDH8`), Locus 38 (`DCC`), and Locus 39 (`XRN2`). Furthermore, for Loci 4 (`rs2222544`), 13 (`rs153429`), 16 (`rs4916723`), 22 (`rs11596214`), and 30 (`rs2279574`), column values are shifted left so that `0` appears under `gene` and `"No protein-coding genes"` appears under `status`. Whether the AI co-scientist hallucinated the numbers in its narrative summary or merged numbers from a different variant/tissue run, this table demonstrates that MCP tool wrapping alone does not prevent downstream LLM synthesis errors.

* **Claim 2 (Cross-agent integration of scCRISPRi and Perturb-seq resolves the `rs887314` psoriasis locus by identifying `GPR137` rather than `BAD` as the likely causal gene, `Fig. 4` & `Supplementary Note 9.2`): Overstated / Confounded by Shared Local Regulation and Asymmetric Gene Exclusion.**  
  In `Fig. 4`, the authors argue that although silencing the `rs887314` cis-regulatory element (CRE) in the `Paper 2` scCRISPRi screen downregulates five nearby genes (`BAD`, `GPR137`, `ESRRA`, `TRMT112`, `PRDX5`), correlating the `rs887314` CRE perturbation signature with single-gene knockdown signatures from `Paper 1` (`Perturb-seq`) across $n = 19\text{--}21$ overlapping genes yields a positive correlation for `GPR137` knockdown (`Rest`: $\rho = 0.56, p = 0.011$; `Stim8hr`: $\rho = 0.68, p = 7.4 \times 10^{-4}$; `Stim48hr`: $\rho = 0.50, p = 0.028$) but not for `BAD` knockdown ($\rho = 0.04\text{--}0.19, p \ge 0.43$), establishing `GPR137` as the primary effector. Three specific issues documented in `Supplementary Note 9.2` (pp. 42–50) undermine this inference:
  1. **Bidirectional CRISPRi cross-repression across a shared promoter/enhancer domain:** As shown in `Supplementary Note 9.2` (pp. 44–45), `rs887314` (`chr11:64,274,779`) is located just **981 bp from the `BAD` TSS** (`chr11:64,275,760`, directly inside the `BAD` promoter region) and 15,623 bp from `GPR137`. In the `Paper 2` scCRISPRi screen, targeting the `rs887314` CRE represses both `BAD` ($\log_2\text{FC} = -1.32, p = 9.25 \times 10^{-28}$) and `GPR137` ($\log_2\text{FC} = -1.37, p = 1.23 \times 10^{-13}$) nearly identically. Crucially, in the `Paper 1` Perturb-seq dataset (`p. 43`), CRISPRi targeting the `BAD` TSS strongly downregulates `GPR137` ($\log_2\text{FC} = -1.25$ to $-1.47, p_{\text{adj}} \le 1.35 \times 10^{-19}$), and CRISPRi targeting the `GPR137` TSS even more strongly downregulates `BAD` ($\log_2\text{FC} = -1.82$ to $-2.65, p_{\text{adj}} \le 1.65 \times 10^{-14}$). Because dCas9-KRAB induces heterochromatin spreading across kilobase-scale domains and because `BAD` and `GPR137` share local cis-regulatory architecture, CRISPRi at either gene is not a clean single-gene loss-of-function perturbation.
  2. **Asymmetric leverage induced by human-directed exclusion of only the knockdown gene (`p. 50`):** In `Supplementary Note 9.2` (`"Steps with human intervention"`, p. 50), the authors disclose that the AI co-scientist initially excluded all five cis-regulated candidate genes (`BAD`, `GPR137`, `ESRRA`, `TRMT112`, `PRDX5`) when computing the downstream transcriptome correlation, and that a human researcher explicitly instructed the agent to *"exclude only the knockdown gene rather than all five candidate genes."* Under this rule, when evaluating `GPR137` knockdown across the $n = 20\text{--}21$ genes (`Fig. 4b`), `BAD` ($\log_2\text{FC} = -1.32$ in `rs887314` CRE perturbation; $\log_2\text{FC} = -1.82$ to $-2.65$ in `GPR137` knockdown) is retained as a data point, creating an extreme bottom-left leverage point (`visible at (-1.32, -2.29)` in `Fig. 4b`) that drives the positive correlation and linear regression slope (`outlier removal` in `Fig. 4b` only drops genes with $|\log_2\text{FC}| > 3$, which retains `BAD`!). Conversely, when evaluating `BAD` knockdown, `BAD` is excluded as the knockdown target, and `GPR137` is the only remaining strongly perturbed gene (`BAD` knockdown alters only 3–4 genes genome-wide in Perturb-seq: `BAD`, `GPR137`, and `UBE3C`, `p. 43`), leaving near-zero signal variance across the other 18–19 cis genes.
  3. **Spurious correlation for a non-regulated control gene (`RPS6KA4`) and undefined filtering to $n = 19\text{--}21$ genes:** Although `Paper 2` tested 438 cis genes within 1 Mb of `rs887314` (`p. 44`) and `Paper 1` measured 13,959 genes (`p. 43`), `Fig. 4b` and `Supplementary Fig. 4` restrict the correlation to $n = 20$ (`Rest`), $n = 21$ (`Stim8hr`), and $n = 19$ (`Stim48hr`) genes without stating the exact inclusion criteria in `Methods`. Moreover, in `Supplementary Fig. 4` (`p. 53`), `RPS6KA4` knockdown also achieves a nominally significant positive correlation at `Stim8hr` ($\rho = 0.44, p = 0.044$) even though `RPS6KA4` is not significantly regulated by the `rs887314` CRE ($p = 0.112$, `Fig. 4a`) and has only a single significant differentially expressed gene (`DMWD`) in Perturb-seq (`p. 43`).

* **Claim 3 (`Paper2Agent` achieves statistically significant accuracy gains over `Claude + Repo` on `AlphaGenome` and `TISSUE` benchmarks, `Fig. 2b–c`, `Methods` p. 11, & `Supplementary Note 4`): Fragile / Pseudoreplicated Across Stochastic Runs and Asymmetrically Prompted.**  
  In `Fig. 2b`, the authors report that on 15 tutorial queries, 15 novel queries, and 30 open-ended queries for `AlphaGenome`, `Paper2Agent` achieves `100.0 ± 0.0%`, `100.0 ± 0.0%`, and `98.7 ± 1.3%` accuracy compared to `60.0 ± 11.5%`, `80.0 ± 4.7%`, and `63.3 ± 6.2%` for the `Claude + Repo` baseline, citing paired $t$-test $p$-values of $p = 8.1 \times 10^{-3}$, $p = 4.2 \times 10^{-3}$, and $p = 5.6 \times 10^{-5}$. Two design flaws affect this comparison:
  1. **Pseudoreplication across $n = 5$ runs instead of testing across $N = 15$ queries:** As documented in `Supplementary Note 4` (`pp. 25, 27, 29`), the authors ran the exact same 15 queries 5 times, computed the average accuracy per run, and performed a paired $t$-test across the $n = 5$ runs ($\text{df} = 4$). Treating repeated stochastic executions of the same fixed prompt bank as independent observations measures LLM decoding variance rather than generalization across queries. On the 15 novel queries, `80.0%` corresponds to $12/15$ correct vs. $15/15$ correct; evaluated at the query level ($N = 15$ paired binary items), an exact two-sided McNemar test of 3 discordant items ($3$ vs. $0$) yields $p = 0.25$, not $p = 0.0042$. (Additionally, item 4 of the grading rubric for the 30 open-ended queries on `p. 29` erroneously states *"across all 15 queries"* due to a copy-paste error.)
  2. **Asymmetric baseline prompt restriction (`p. 23`):** During agent synthesis (`Step 2`), `Paper2Agent` executes the repository's tutorial notebooks and extracts its MCP tools directly from those tutorial cells. However, during evaluation (`Supplementary Note 4`, p. 23), the `Claude + Repo` baseline was given a negative constraint explicitly forbidding it from using the tutorial notebooks: *"Do NOT provide answers from tutorial notebooks or the executed cells of ipython notebooks. You must: 1. Write Python code to query the AlphaGenome API directly..."* Forbidding the baseline agent from consulting or reusing the executed tutorial notebooks while evaluating it on 15 queries drawn directly from those tutorials (`Tutorial Queries`) creates an artificial handicap.

* **Claim 4 (`Paper2Agent` reduces query cost by $2.8\times$ and execution time by $6.3\times$ relative to the baseline, `Main Text` p. 6 & `Supplementary Note 7` p. 31): Numerically Inconsistent.**  
  In `Supplementary Note 7` (`p. 31`), the authors write: *"During evaluation, Paper2Agent answered benchmark questions at an average cost of $0.20 per query in 1.6 minutes, compared to $0.38 per query in 4.3 minutes for the baseline, corresponding to a 2.8× cost reduction and 6.3× speedup."* The arithmetic is internally inconsistent: $\$0.38 / \$0.20 = 1.90\times$ (not $2.8\times$), and $4.3\text{ min} / 1.6\text{ min} = 2.69\times$ (not $6.3\times$). Even in `Supplementary Fig. 3` (`p. 52`), the plotted bars for `Paper2Agent` (`$0.20`, `1.6 min`) vs. `AlphaGenome Repo` (`$0.46`, `6.1 min`) correspond to ratios of $\$0.46 / \$0.20 = 2.30\times$ and $6.1 / 1.6 = 3.81\times$, neither of which matches the `2.8×` and `6.3×` figures reported in `Main Text` (p. 6) and `Supplementary Note 7` (p. 31).

### 3. CONSTRUCTIVE AND DOABLE SUGGESTIONS FOR IMPROVEMENT

1. **Audit and regenerate `Supplementary Table 1` (`ADHD` variant interpretations):**  
   Trace the pipeline bug that caused the `AlphaGenome` quantile scores cited inside the `interpretation` text of `Supplementary Table 1` (pp. 58–60) to diverge from the numeric `splice`, `rna_seq`, `dnase`, and `chip_tf` columns across >20 of the 39 loci (and fix the column-alignment shift at Loci 4, 13, 16, 22, and 30). If the AI co-scientist generated those numbers during free-text synthesis rather than reading them deterministically from the tabular output, add a programmatic verification step that cross-checks numerical values cited in agent prose against the underlying tool call JSON before reporting.

2. **Recompute the `rs887314` cross-screen correlations under symmetric gene-exclusion rules and reframe the causal claim (`Fig. 4`, `Supplementary Note 9.2`):**  
   * Report the Spearman correlation and regression slope for `GPR137` knockdown, `BAD` knockdown, `TRMT112` knockdown, `ESRRA` knockdown, and `PRDX5` knockdown under a **symmetric exclusion rule** where **all five cis candidate genes within the shared regulatory locus** (`BAD`, `GPR137`, `ESRRA`, `TRMT112`, `PRDX5`) are excluded from the downstream gene set (matching the agent's original unsteered specification on `p. 50`), so that the correlation measures genuinely *trans*/downstream network concordance rather than direct cis co-repression of `BAD` ($\log_2\text{FC} = -2.29$) when targeting `GPR137`.
   * Explicitly state in `Methods` how the $n = 19\text{--}21$ overlapping genes in `Fig. 4b` were filtered from the 438 cis genes tested in `Paper 2` and 13,959 genes in `Paper 1`, and report the correlation across all expressed overlapping genes and all significantly differentially expressed genes.
   * Reframe the biological interpretation of `rs887314` to acknowledge that `rs887314` sits 981 bp from the `BAD` TSS and that dCas9-KRAB targeting either `BAD` or `GPR137` strongly represses both genes (`p. 43`), making it impossible to rule out coregulation or dCas9-KRAB heterochromatin spreading without CRISPR base editing or prime editing of `rs887314`.

3. **Replace run-level pseudoreplicated $t$-tests with query-level inference and remove the asymmetric baseline prompt handicap (`Fig. 2b–c`, `Supplementary Note 4`):**  
   * Report item-level statistical comparisons (e.g., McNemar's test or a mixed-effects logistic model with random intercepts for query and run) where the sample size is the number of independent queries ($N = 15$ or $N = 30$), rather than a $t$-test across $n = 5$ repeated runs of the same fixed queries.
   * Evaluate the `Claude + Repo` baseline without the negative prompt constraint forbidding it from inspecting tutorial notebooks (`p. 23`), so both `Paper2Agent` and the baseline have symmetric access to the repository's documentation and examples.

4. **Reconcile the cost and runtime arithmetic (`Main Text` p. 6, `Supplementary Note 7` p. 31, `Supplementary Fig. 3` p. 52):**  
   Correct the stated cost reduction and speedup multiples so they match the reported numerator and denominator (`$0.38 / $0.20 = 1.9×` and `4.3 min / 1.6 min = 2.7×`, or reconcile the text numbers `$0.38` and `4.3 min` with the `$0.46` and `6.1 min` values plotted in `Supplementary Fig. 3`).
