### 1. SUMMARY AND OVERALL IMPACT STATEMENT

#### Executive Summary
This Application Note summarizes the architectural, algorithmic, and model extensions introduced in RAxML version 8 since the 2006 RAxML-VI-HPC release. The software integrates four bootstrap support flavors (standard non-parametric, rapid bootstrap, SH-like aLRT support, and RELL), ascertainment bias corrections (Lewis, 2001) for morphological and SNP alignments, heterogeneous protein mixture models (LG4M, LG4X), parallelization across PThreads, MPI, and x86 vector intrinsics (SSE3, AVX, AVX2), memory-saving gappy alignment structures, short-read/fossil placement via the Evolutionary Placement Algorithm (EPA), and tree post-analysis metrics including Tree Certainty (TC), Internode Certainty (IC), and a reference-subset plausibility checker. Source code is publicly available under the GNU GPL on GitHub alongside a 50-page manual.

While RAxML v8 is an indispensable, battle-tested computational engine for maximum likelihood phylogenetics, the manuscript itself functions strictly as a high-level feature digest. Most algorithmic innovations (rapid bootstrapping, EPA, bootstopping, memory compression) were benchmarked in prior standalone papers, leaving the newly introduced features in this note—specifically the RELL implementation, TC/IC calculations, the unpublished sliding-window phylogenetic signal scanner, and the AVX/AVX2 intrinsics—supported by minimal empirical validation (a single uncharacterized DNA alignment runtime test in Section 2.6). Providing reproducible benchmark specifications and formal definitions for the unpublished sliding-window algorithm would substantially strengthen the technical record.

### 2. SPECIFIC CONCLUSIONS AND ASSESSMENT OF SUPPORT

#### Detailed Rubric Evaluation

* **Claim 1 — Vector intrinsics (SSE3, AVX, AVX2) substantially accelerate maximum likelihood and parsimony calculations (111.5 s unvectorized vs. 84.4 s SSE3 vs. 66.22 s AVX, with <5% further gain from AVX2): [Moderately Supported].**  
  Section 2.6 reports wall-clock runtimes on an Intel i7-2620M (2.70 GHz) processor. However, the benchmark dataset is described only as "a small single-gene DNA alignment using the $\Gamma$ model of rate heterogeneity" without specifying the number of taxa, alignment length, percentage of gappy/invariant sites, or starting tree seed. Furthermore, the Intel i7-2620M (Sandy Bridge microarchitecture) does not support AVX2 (which was introduced in Intel Haswell); the hardware used to evaluate the "<5% run time improvement" between AVX and AVX2 is omitted.

* **Claim 2 — RAxML v8 accurately implements expanded substitution models (GTR for proteins, LG4M, LG4X, ML base frequencies) and Lewis (2001) ascertainment bias correction across binary, multi-state morphological, and SNP datasets: [Well Supported].**  
  Section 2.2 grounds these additions in established likelihood formulations (Lewis, 2001; Le et al., 2012), and the open-source C codebase allows direct verification of the transition probability and conditional likelihood vector adjustments. Nevertheless, no validation accuracy or runtime overhead metrics are shown for free-parameter protein GTR estimation or ascertainment correction on SNP matrices where constant sites are excluded.

* **Claim 3 — Post-analysis operations (RELL bootstrap, SH-like support, rogue taxon detection, Tree/Internode Certainty, and the plausibility checker) scale to phylogenies with tens of thousands of taxa: [Moderately Supported].**  
  The underlying algorithms for consensus trees (Aberer et al., 2010), rogue taxa (Pattengale et al., 2011), and TC/IC (Salichos and Rokas, 2013) are cited, and the plausibility checker cites a technical report (Dao et al., 2013). However, no memory or runtime scaling numbers are presented in the text for computing RELL or TC/IC on trees with $10^4$–$10^5$ tips.

* **Claim 4 — An unpublished sliding-window algorithm identifies gene regions (e.g., 16S) with strong and stable phylogenetic signal to guide amplicon selection: [Fragile].**  
  In Section 2.5, the author introduces an "unpublished" sliding-window approach for next-generation sequencing assay design, but provides no mathematical definition of the window objective function, step size, topological stability metric, or empirical validation on 16S rRNA data.

### 3. CONSTRUCTIVE AND DOABLE SUGGESTIONS FOR IMPROVEMENT

#### Major Issues, Minor Issues & Concrete Recommendations

#### 1. Document Benchmark Dataset Dimensions and Hardware for AVX vs. AVX2 Comparisons (Major Issue)
* **WHY:** Reporting exact runtimes (111.5 s, 84.4 s, 66.22 s) in Section 2.6 without dataset dimensions ($N$ taxa, $L$ sites, site patterns) or the exact Haswell CPU model used for the AVX2 comparison prevents independent reproduction of the vectorization speedups.
* **WHAT:** Specify the exact test alignment and CPU architectures in Section 2.6 or Supplementary Data.
* **HOW:** Add a 4-row summary table listing the alignment name/accession, number of taxa, number of distinct site patterns, compiler flags (`-msse3`, `-mavx`, `-mavx2 -mfma`), and exact CPU models used for the Sandy Bridge (SSE3/AVX) and Haswell (AVX2) timing runs.

#### 2. Formally Define or Benchmark the Unpublished Sliding-Window Signal Algorithm (Major Issue)
* **WHY:** Section 2.5 advertises an unpublished sliding-window algorithm for 16S amplicon selection without stating how "strong and stable phylogenetic signal" is quantified (e.g., Robinson-Foulds distance of window trees against a full-length reference tree, EPA placement accuracy, or internode certainty).
* **WHAT:** Provide the mathematical formulation of the sliding-window statistic and state the command-line flag that invokes it.
* **HOW:** Add a brief paragraph in Section 2.5 (or the Supplementary Material) specifying the window length $W$, stride $S$, the tree comparison metric computed per window, and the corresponding `-f` option in RAxML v8.

#### 3. Clarify Ascertainment Bias Assumptions for Filtered SNP Matrices (Minor Issue)
* **WHY:** Section 2.2 notes that Lewis's (2001) standard conditional likelihood correction is useful for SNP alignments containing only variable sites. In practice, SNP matrices often exclude singletons or apply minor allele frequency thresholds, or retain invariant sites within flanking reads, where standard $L_{\text{var}} = (1 - P(\text{const}))^{-1}$ conditioning can bias branch lengths if applied naively.
* **WHAT:** Clarify which flavours of ascertainment bias correction (standard Lewis vs. Felsenstein/Stamatakis invariant-site count corrections) are implemented.
* **HOW:** Explicitly state the command-line model suffixes (e.g., `ASC_GTRGAMMA`) and note whether users can supply the exact counts of invariable A, C, G, and T sites.

#### 4. Editorial and Bibliographic Cleanup (Minor Issue)
* **WHY:** Minor typographical errors in the text and bibliography detract from the polish of the note.
* **WHAT & HOW:**
